# B2.2 Offline Release-Candidate Qualification Record

## Scope

This document records the qualification status of the Shelly TRV Gen1 experimental build:

```text id="q1b6xn"
B2.2
```

B2.2 is an observer-free integrated firmware candidate containing all demonstrated, safely correctable and independently qualified defects selected for this build.

Its current disposition is:

```text id="gkixuz"
B2.2 OFFLINE RELEASE-CANDIDATE GO
```

This statement has a deliberately narrow meaning.

It means:

> The B2.2 application and GBL passed the defined offline behavioral, composition, binary-construction and independent-verification qualification gates.

It does **not** mean:

- B2.2 has been flashed to a physical TRV
- B2.2 is hardware-qualified
- B2.2 has passed a long-term battery test
- B2.2 is a production release
- the historical battery-drain root cause has been proven
- battery-life improvement has been demonstrated

No physical TRV was contacted as part of the B2.2 qualification documented here.

B2.1_OBS was frozen for long-term hardware observation.

Reverse engineering and qualification performed afterward identified several additional defects that met the project's correction criteria.

Rather than modifying the active hardware experiment, those corrections were integrated into a separate offline candidate.

This preserves:

```text id="ff4qqh"

```

while allowing:

```text id="0er81b"
additional demonstrated defects
to be corrected and qualified offline
```

The two activities are therefore intentionally separated.

# 7. A1 Experimental Regression

The original experimental A1 implementation was later found to mishandle verified temporary `request1` override paths.

Five native paths were verified:

```text id="gs7n20"
physical button
HTTP /psovrd
Cloud psovrd
SSI settings_sta
OTA launcher
```

The intended behavior is:

```text id="b84zl0"
selected policy = 3

temporary request = 1

use 1 temporarily

restore 3
```

The old A1 implementation could allow the temporary state to become persistent.

For example:

```text id="675kc3"
3/3
 |
 v
temporary 1
 |
 v
1/1
```

instead of restoring policy 3.

This regression was introduced by the experimental A1 patch.

It is not a stock Shelly defect.

# 13. Correction 3 — B2 Bounded Serialization

B2 is a host-side reference counter representing software owners that currently require an EM1-level sleep restriction.

Conceptually:

```text id="8v7f39"
B2 = 0
no active EM1 owner

B2 = 1
one active owner

B2 = 2
two active owners
```

Stock firmware contains a demonstrated task-preemption/lost-update race in relevant B2 read-modify-write operations.

---

# 14. B2 Failure Modes

The race can produce:

```text id="f86mye"
phantom contribution
```

where B2 remains elevated after the legitimate owner is gone.

This can unnecessarily restrict host sleep toward EM1.

It can also produce:

```text id="w2nxhg"
lost contribution
```

where an active owner is no longer represented in B2.

This can allow a deeper sleep state while ownership remains active.

Both violate the reference-count invariant.

---

# 15. B2 Correction

The correction applies bounded serialization to the complete relevant B2 read-modify-write operation.

It preserves:

```text id="ye53lb"
reference-counter semantics
```

It does not:

```text id="n4uhgg"
force B2 = 0
```

and does not:

```text id="xym6c2"
convert B2 to Boolean state
```

Multiple simultaneous owners remain supported.

# 30. Correction 8 — P02 I2C Timeout Retirement

A demonstrated I2C timeout lifecycle defect was identified.

The timeout path can return while the transaction remains incompletely retired.

Relevant residual state can include enabled interrupt handling and unfinished transaction state.

The violated invariant is:

> A timed-out I2C operation must be retired into a bounded known state before control returns.

P02 adds bounded retirement of the timed-out I2C operation.

The correction ensures the timeout path does not simply abandon active transaction state.

It is designed to preserve normal successful I2C behavior while making timeout cleanup deterministic.

# 39. mDNS Is Not Part of B2.2

Historical Patch B and A+B experiments investigated periodic mDNS behavior.

B2.2 does not include an mDNS suppression patch.

This is intentional.

Historical testing demonstrated that targeted mDNS suppression alone did not prevent drain on `.77`.

The project therefore does not treat mDNS suppression as a required component of the current corrected candidate.

---

# 40. EM3 Is Not Enabled

B2.2 does not clear B3 and does not force EM3.

The TRV's normal host sleep architecture uses persistent B3 ownership such that intended deepest normal idle is EM2.

Enabling EM3 would introduce a substantially different low-frequency-clock/tickless design question.

It is therefore not part of B2.2.

---

# 41. Observer Absence

B2.2 is intentionally observer-free.

Qualification explicitly verifies that the PM52→cmd66 observer used in B2.1_OBS is absent.

This includes absence of the observer's:

- diagnostic allocation
- observer control flow
- observer readout implementation
- first-fault ring behavior

B2.2 must not be described as B2.1_OBS with additional fixes.

It is a separate observer-free candidate.

---

# 42. Why Observer Removal Matters

The long-term B2.1_OBS observer is designed for low intrusion, but diagnostic instrumentation is not automatically desirable in a final candidate.

B2.2 therefore represents the direction:

```text id="wt3ijq"

```

This reduces unnecessary final-code complexity.
